## HWPX 검증 툴체인 이식 (2026-08-01)

위 kordoc 시험 생성은 구조 검증과 한컴 실열림을 확인하지 못한 채 끝났다. `Hwp_doc`에서
검증된 hwpx 툴체인(스크립트 14개 + base 스켈레톤 11종 + 템플릿 4종)을
`.claude/skills/hwpx/`로 이식해 그 구멍을 메웠다.

**환경:** Python 3.12.10 / lxml 5.4.0 / pywin32 / python-hwpx 전부 설치 확인.

### 파일럿 6종 전수 검증 — 전부 PASS

`validate` → `fix_namespaces` → `finalize --strip-linesegarray` → `validate --layout`
→ `finalize --hancom` 순으로 6종 전부 실행.

- 구조 검증 6/6 PASS, 네임스페이스 보정 0건(고칠 것 없음).
- `strip_linesegarray_removed: 0` — kordoc 산출물에는 줄배치 캐시가 없다. 가이드 §6의
  실패 지점 2번(linesegarray 잔존)은 이 경로에 해당하지 않는다.
- **한컴 COM 실열림 6/6 PASS.** 잔존 Hwp.exe는 COM 종료 과정의 꼬리로 스스로 종료됨.

### 쪽수 실측 — reflow 근사가 정확했다

한컴 COM으로 실제 쪽수를 읽어 kordoc reflow 예상과 대조: **6/6 일치**
(중등 4·2·2 / 초등 4·3·2). 위에 남겨 둔 "reflow는 근사" 우려는 적어도 이 문서군의
쪽수 총량에 대해서는 해소됐다. 단, 쪽수 일치가 **페이지 안쪽 배치**(헤딩이 페이지 끝에
홀로 남는 것)까지 같음을 증명하지는 않는다 — 그건 여전히 육안 확인 사항이다.

### 이식 중 발견한 결함 1건 (수정함)

`scripts/office/unpack.py`가 ZIP 디렉터리 엔트리를 빈 파일로 써서, 그 아래 실제 엔트리가
부모 디렉터리를 만들지 못하고 `FileExistsError`로 죽었다. kordoc 산출물은 디렉터리
엔트리 3개(`META-INF/`·`Contents/`·`Preview/`)를 포함하는데 스킬 템플릿 산출물은 0개라,
Hwp_doc 환경에서는 드러날 일이 없던 잠복 결함이다. `infolist()` + `is_dir()` 건너뛰기로
수정 → 경로 B 왕복 VALID + 한컴 실열림 PASS, 디렉터리 엔트리 없는 파일에 대한 회귀도 없음.
**원본(Hwp_doc)에는 같은 결함이 남아 있다 — 작업 공간 규칙상 손대지 않았다.**

### HWPX 레이아웃 보정 (2026-08-01, 사용자 PDF 대조 후)

사용자가 한글에서 6종을 PDF로 내보내 원본 HTML과 대조를 요청 → Edge headless로 원본
HTML도 PDF화해 pymupdf로 정량 비교(괘선 y좌표 간격 = 행 높이 실측). **내용·인코딩은
온전했으나 레이아웃 3계열이 무너져 있었다**: ① 답란 크기 붕괴(중등 설계표 108pt→45pt,
초등 답란 5줄→2줄, 그림칸 150pt→189/125 제각각), ② 콜아웃 박스 소실로 위계 붕괴 +
동일 문구 라벨이 두 줄 연속 노출, ③ 상단 여백 4배(원본 29pt vs 121.6pt). 근본 원인:
마크다운 경유에서 원본 HTML의 pt 명세가 전부 탈락했는데 `<br>` 개수로 눈대중 근사했다.
**원본 HTML에 정확한 값이 있었는데 참조하지 않은 것이 1차 실수.**

보정은 이식한 툴체인으로 unpack → section0.xml 직접 패치 → pack (fix_layout.py):

- `hp:cellSz`/`hp:sz` height를 원본 명세로: 설계표 10800, 그리기표 7400, 그림칸 15000
  (1pt = 100). 셀 안 빈 문단은 1개로 트림 — 높이는 속성이 지배하게.
- secPr `hp:margin` top 8504→4252, header 2835→1417 (상단 113pt→64pt). 6종 전부.
- 임의 섹션 번호 제거, 중복 라벨 문단 삭제, '줄어듦'→'↓' 복원.
- **글자처럼 취급(treatAsChar=1) 표는 행 분할이 안 된다** — 447pt 설계표가 1쪽 잔여
  공간에 못 들어가 통째로 넘어가며 큰 공백 발생. 셀 높이를 줄여 끼워 맞추는 것은
  여백 변화에 취약하므로, 섹션 헤딩 `hp:p pageBreak="1"`로 결정론적 쪽 나눔을 택했다.

결과: 전수 파이프라인 재통과 + 한컴 COM PDF 내보내기 실측 — 설계표 108pt×4,
그리기표 74pt×4, 그림칸 150pt×2, 상단 여백 64.4pt. 쪽수 초4·3·2 / 중4·2·3
(중등 학습지 2→3p는 답란 복원의 정상 결과).

**3단계 어댑터 교훈:** ① 치수의 단일 소스는 원본 렌더러의 pt 명세다 — lesson.json →
section0.xml 직접 생성으로 가고 마크다운을 경유하지 않는다. ② 큰 고정높이 표 앞에는
쪽 나눔 로직이 필요하다(잔여 공간 < 표 높이면 pageBreak). ③ 미해결 잔여: 콜아웃
박스(테두리)·표 헤더 음영 — borderFill 추가가 필요해 XML 직접 생성 단계로 미룸.
④ 사용자가 만든 pilot/*/out/*.pdf는 보정 전 버전 기준이라 이제 구본이다.

**출처 라이선스 확인이 선행 조건**이다.

## Task 3 노트 정정 — 학년 밴드 감지

Task 3에서 `"초4 (Grade 4)"` 형태로 병기하면 감지된다고 적었으나 **틀렸다.**
`grade_number()`는 `shared.grade`에서 **첫 번째 숫자**를 취한다(`re.search(r"\d{1,2}", s)`).
`"중학교 2학년 (Grade 8)"` → 2로 읽혀 초1–2 밴드(답란 200pt)로 강등됐다.

**확정 규칙: 영문 학년을 앞에 쓴다** — `"Grade 8 · 중학교 2학년"`, `"Grade 4 · 초등학교 4학년"`,
`"Grade 10 · 고등학교 1학년"`. 검증: 중 → 8 → 130pt/줄노트 없음, 초4 → 4 → 150pt/줄노트.
`shared.grade`는 산출물에 출력되지 않음을 확인(교사 눈에 안 보임). science.md 매핑 절에 명문화.

## 2단계 — HWPX 어댑터 구현 실측 (2026-08-01)

`render_lesson_hwpx.py` — ADR-4 개정판(OWPML 직접 생성) 이행. 표준 라이브러리만 사용,
lesson_common을 import해 docx 렌더와 같은 치수 계산을 공유한다. 패키지 구조·페이지
여백·서식 참조표는 위 보정본에서 검증된 값을 기반으로 borderFill 4종(헤더 음영·콜아웃·
괘선·연한 상자)을 추가.

**전수 검증 (입력 4종 = 파일럿 3 + 스모크 ko → hwpx 11개):**

- 구조 검증 11/11 PASS, 레이아웃 경고 0
- 한컴 COM 실열림 11/11 PASS. 쪽수 실측: 중 5·2·3 / 초 4·2·2 / 긴급 4·2·3
  (보정본 중 4·2·3 / 초 4·3·2 대비 ±1 이내 — 추정 고정 높이의 여백 차)
- **치수 대조: 고정 높이 행이 docx 렌더러와 전 항목 일치** — 괘선 24/28pt, 설계표
  48.6pt(0.45×밴드), 관찰표 74pt(JSON 명시값), 그림칸 150pt. answer_profile /
  table_row_height를 그대로 import하므로 구조적으로 어긋날 수 없다.
- 한컴 COM PDF 내보내기 3종 육안: 콜아웃 박스(borderFill fill)·표 헤더 음영·괘선
  답란·설계표·관찰표 전부 렌더 확인, U+FFFD 0. 보정본의 미해결 2건(콜아웃 테두리·
  헤더 음영)이 이 경로에서 해소됐다.
- 크롬 언어: HWPX는 한국어(성취기준·분·준비물·학생에게 보이는 과제), docx는 동결이라
  영어 유지 — 의도된 비대칭. 콜아웃 아이콘은 KS X 1001 문자로 예방 치환(★·※·◆).

**근사로 남긴 것:** columns는 순차 방출(원본은 2열 표), number_line은 양끝값 문구 +
빈 상자, docx가 auto 높이인 셀은 내용 길이 기반 추정 고정 높이(한글이 내용에 맞춰
늘리므로 잘림 없음 — PDF로 확인). 쪽 나눔은 y 근사 추적으로 큰 고정높이 표 앞에서만
전환한다.
